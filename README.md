# I’MON Web

Самостоятельный сайт агентства I’MON на **Next.js 16 + Payload CMS 3**. Публичная часть и редакционная панель работают в одном приложении, без зависимости от визуального конструктора. Визуальная основа — приобретённый агентством шаблон, дополненный материалами I’MON.

## Что входит

- 23 адреса исходного сайта: основные разделы, 8 кейсов, 8 материалов журнала, юридические разделы.
- Гибкая CMS: страницы, блоки, кейсы, журнал, навигация, глобальные контакты, медиатека.
- Черновики, публикация, история версий, редактор и администратор.
- Адаптивная типографика, мобильное меню, фильтры, медиа, FAQ, формы, локальные шрифты.
- Серверные заявки с валидацией, согласием и ограничением по количеству.
- Сохранённые 134 уникальных исходных медиафайла. Оптимизированное видео для первой секции.
- Первичная миграция идемпотентна: не перезаписывает уже отредактированные записи.

## Быстрый запуск (Node.js 24)

```bash
corepack enable
pnpm install --frozen-lockfile
cp .env.example .env
```

В файле `.env` укажите случайный секрет **не короче 32 символов**, не публикуйте его в Git:

```dotenv
DATABASE_URL=file:./imonbuildweb.db
PAYLOAD_SECRET=CHANGE_ME_TO_A_LONG_RANDOM_STRING_AT_LEAST_32_CHARS
NEXT_PUBLIC_SERVER_URL=http://localhost:3000
IMON_ADMIN_EMAIL=info@imon.agency
```

Затем:

```bash
pnpm generate:types
pnpm seed
pnpm setup:admin
pnpm dev
```

Сайт: **http://localhost:3000**. Панель администратора: **http://localhost:3000/admin**.

`pnpm setup:admin` создаёт первого администратора только при пустой таблице пользователей. Временный пароль записывается **только на локальный компьютер** в `.initial-admin` (права 0600), а не в stdout, Git или лог. После первого входа необходимо сменить пароль и обеспечить HTTPS.

### Команды

```bash
pnpm check
pnpm lint
pnpm build
pnpm start
pnpm seed             # повторный запуск безопасен для уже существующих записей
pnpm localize         # заменить только остаточные английские вводные шаблона
pnpm setup:admin
```

## Редактирование

| Раздел CMS | Что управляется |
| --- | --- |
| Страницы | Адрес, первый экран, локальное видео, блоки, SEO, черновики |
| Кейсы | Адрес, клиент, обложка, рубрика, год, порядок, секции |
| Журнал | Заголовки, рубрики, обложки, тексты, разделы |
| Медиатека | Загрузка новых изображений, видео и PDF, alt-тексты |
| Навигация | Названия и URL меню, контактная CTA |
| Настройки | Бренд, рабочая почта, Telegram, тексты футера |
| Заявки | Сообщения с формы, статус обработки |

**Важно:** оригинальные медиа лежат в `public/media/` и используются на импортированных страницах. Новые медиа можно загружать в CMS и привязывать к блокам. CMS-uploads хранятся отдельно в `uploads/`; при переносе на другой сервер сохраняйте эту папку и базу данных.

## Деплой на собственном сервере

Проект рассчитан на постоянно работающий Node.js-сервер (например, VPS), а не GitHub Pages. CMS требует постоянной БД и сохранённого каталога загрузок.

Пример Docker Compose: сначала создать `.env` с полноценным секретом, указать публичный HTTPS-домен в `NEXT_PUBLIC_SERVER_URL`, затем:

```bash
docker compose up -d --build
docker compose exec web pnpm seed
docker compose exec web pnpm setup:admin
```

У Docker Compose предусмотрены постоянные named volumes для SQLite и медиа CMS. На реальном домене используйте HTTPS через reverse proxy, периодические копии БД (с учётом SQLite WAL) и каталога uploads, контроль доступа к `/admin` и мониторинг ошибок. Для высоконагруженного/многорепличного окружения вместо SQLite понадобится PostgreSQL и отдельное объектное хранилище. **Не подключайте SQLite к serverless-деплою с эфемерным диском.**

## Контент, требующий подтверждения до публичного запуска

1. Англоязычные статьи и часть исходных демонстрационных кейсов унаследованы от приобретённого шаблона. Они **не должны считаться подтверждёнными работами агентства**. Статьи импортированы в черновики; исходные URL доступны только как наследуемый просмотр и закрыты от индексации.
2. Исходные английские тексты, фиктивная команда, адреса американского агентства и шаблонные ссылки заменены или не используются. Для связи указан `info@imon.agency` и Telegram `@imonagency`; проверьте актуальность перед публикацией.
3. Страницы «Конфиденциальность» и «Условия использования» сейчас содержат **явно помеченные материалы для юридического согласования**. Их нельзя публиковать как полноценные юридические документы.
4. Заявки сохраняются в БД. Отдельная отправка уведомлений на email/CRM **не подключена**: нужно указать согласованный сервис, настроить SPF/DKIM/DMARC и провести тест доставки, если она требуется.
5. Студийные фотографии, исходные медиа и материалы приобретённого шаблона требуют соблюдения условий соответствующих лицензий при повторном распространении.

## Технические детали

- Исходная карта из sitemap и извлечённая разметка: `tools/capture_source.py`.
- Медиабаза и загрузчик: `tools/download_media.py`; контентная выборка: `tools/build_seed.py`.
- Контентный fallback: `src/content/source.json`. Он нужен для первичного запуска до миграции.
- Точки расширения CMS: `src/collections`, `src/globals`, `src/blocks`.
- Конфиденциальные данные, SQLite, `.env`, логи аудита и uploads исключены из Git.
