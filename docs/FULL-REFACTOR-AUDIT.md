## 2. Корневые причины недостаточного первоначального переноса

1. **Две системы правды** — отдельные секции сначала жёстко зашивались в коде вместо сохранения схемы/данных в CMS. Это не позволяло редактору менять реальный порядок и содержание. Рендерер главной теперь обходит CMS-блоки в заданном порядке; другие специальные страницы также связаны со структурой контента.
2. **Дублированная вёрстка** — фрагменты и медиа могли отображаться универсальными секциями вместо исходной редакционной композиции. Созданы отдельные композиции для кейсов, главной, раздела «О нас», журнала и контактов, но необходимо сравнение на нескольких положениях прокрутки, а не только первых экранов.
3. **Нет управления движением** — GSAP-сценарии ранее были зашиты в компонентах. Добавлены декларативные пресеты движения к настройкам слоёв (с CSS-переменными и ScrollTrigger). Для сложных таймлайнов потребуется отдельная модель.
4. **Хрупкие положения контента** — некоторые секции опираются на фиксированные высоты и крупные заголовки. Файловые CSS-селекторы для наложений Askona заменены именованными композициями CMS. Отрицательные смещения остались управляемыми через адаптивные свойства слоя. Нужны сравнительные снимки и тесты переполнения на 1440/768/390 и узких промежуточных ширинах.
5. **Несогласованная схема SQLite** — dev-mode schema push вступал в конфликт с версионными миграциями, приводил к HTTP 500. Отключено автоматическое изменение схемы и подготовлены миграции. Любые изменения на продакшене выполнять через проверенный upgrade с резервной копией.
6. **Ненадёжная проверка UI** — успешная сборка не выявляла проблемы внутри редактора. Добавлены интеграционные тесты CRUD черновиков, публикации, приватности, сохранения, конфликтов версий и работы холста в настоящем Chrome.

## 4. Зафиксированные проверки

- Автотесты модели и CSS-ограничений покрывают клонирование, стабильные ID, нормализацию стилей, безопасность ввода, медиассылки и адаптивные наследования.
- Интеграционный сценарий подтверждает: анонимный доступ, авторизацию, черновики, отдельную публикацию, обработку конфликтов, ссылочную безопасность, сохранение опубликованной версии при новых черновиках, историю, редактирование текста и перестановку секций на настоящем холсте, адаптивы, сохранение дизайна, анимационных пресетов и направляющих. Все тестовые данные убираются после успешного прогона.
- Предыдущий аудит проверил 23 URL на трёх ширинах (69 проверок): без HTTP-ошибок и ошибок JS; нашли переполнение юридического заголовка на 390px и один ложный сигнал на скрытом для зрячих тексте. CSS заголовков исправлен; повторный прогон 69 маршрутов/размеров завершился без HTTP-ошибок, JS-исключений, сломанных загруженных изображений и переполнений.
- Оригинальные логины и конфиденциальные данные не добавляются в Git; отдельный Studio worktree содержит изолированную копию SQLite.

Логи/скриншоты тестирования лежат в исключённой из Git папке `audit/` и могут быть сверены на Mac. **Не выдавать компиляцию или пройденный API-тест за подтверждённую визуальную идентичность.**

**P0 · Запуск редактора и воспроизводимость.** Повторный UI regression всего редактора на production build; сохранение дизайна, стилей и анимации; устранение всех 4xx/5xx; отсутствие утечки черновиков; миграции и резервная копия.

**P1 · Максимальное сближение с визуальным редактором.** Глобальные дизайн-токены и типографические стили, библиотека компонентных вариантов, расширенная модель анимаций, более полное редактирование структур и медиа без кода.

**P1 · Визуальное соответствие сайту.** Попарные десктопные/мобильные снимки каждого адреса, типографика, отступы, анимации, скролл, скорость. После исправления геометрии — проверка динамической смены текста в CMS.

**P2 · Продакшен-инфраструктура.** PostgreSQL/объектное хранилище при масштабировании, staging preview по HTTPS, приём заявок в согласованную CRM/почту, деплой с откатом, мониторинг, бэкапы и проверка доступов.

**Контентные блокеры перед публичным запуском:** демонстрационные работы и публикации, оригинальные фотографии команды, юридические страницы и отсутствие доставки уведомлений с формы. Эти пункты не решаются рефакторингом.
