# I’MON: анализ замены Framer и архитектуры визуального редактора

Дата: 21 октября 2026. Изолированная ветка: `feat/framer-parity-20261021`.

## Цель

Публичный сайт обязан сохранять визуальную композицию купленного шаблона: геометрию, медиаконтент, анимации, типографику, навигацию, плавность. Тексты, контактные данные и изображения, которые относятся к чужому демо-агентству, являются контентными заглушками; переносить чужое имя/авторство как факты о I’MON нельзя.

Редактор должен обеспечивать прямое редактирование текста, добавление/перемещение блоков, вложенные компоненты, медиатеку, вариативные брейкпоинты, дизайн-токены, CMS коллекции, историю изменений, публикацию и визуальную настройку анимаций, не заставляя открывать код.

### Framecoded — измеренный эксперимент, не оценка по README

CLI запущен на `https://fantastic-future-931954.framer.app/` в режиме отрисовки для двух страниц.
* Home desktop, высота: **9212 px (оригинал) / 9212 px (выгрузка)**.
* Home mobile: **9847 / 9825 px**.
* About desktop: **8184 / 8311 px**.
* About mobile: **9222 / 9291 px**.
* Реальная ошибка выгрузки: отсутствует шапка на главной; часть API/props типизирована неверно, а MotionRuntime имеет ошибки типов. Исправление узких типовых ошибок (табиндекс, HTML name, MotionRuntime casts) позволило собрать 2-страничный экспорт; это не исправляет отсутствие header или отсутствующую Payload-интеграцию. Значит размеры не доказывают функциональную идентичность.
* Motion data для Home и About действительно извлекаются; этот материал полезен как спецификация анимаций. Не переносить многомегабайтные файлы анимации из экспорта напрямую без анализа.

Экспериментальные исходники и сравнительные изображения находятся **вне Git-репозитория** на Mac, в `/Users/erdc/Projects/imon-builder-research/`. Они не используются как production dependency.

### Revyme — юридический и архитектурный вывод

Revyme использует реальный AST/TSX-документ, его ProjectFS и runtime; I’MON использует Payload коллекции, SQLite, управляемые версии и SSR на Next.js. Для интеграции недостаточно скопировать визуальные панели. Необходимы:
1. Адаптер ProjectFS <-> CMS с транзакционной записью и конфликтами версий.
2. Безопасный рендерер и механизм публикации JSX без произвольного исполнения недоверенного кода.
3. Миграция всех компонентов, маршрутных шаблонов и медиа с проверкой соответствия оригиналу.
4. Юридическое решение: AGPL с публикацией модифицированного источника/сохранением NOTICE или коммерческая лицензия. **Без этого не переносить исходный код Revyme в I’MON.**

## Принятое решение текущей итерации

* Сохраняем публичный код I’MON и Payload как одну рабочую систему данных. Не смешиваем две независимые CMS и два DOM-рендерера.
* Сравниваем сайт с оригиналом браузерными измерениями на 1440/390 и переводим несоответствия в точные CSS/компонентные правки, без художественного редизайна.
* Framecoded применяется как независимый инструмент референс-экспорта и анализа motion, но не как замена production сайта, пока не пройдёт TS, SEO, header, формы и взаимодействия.
* Текущий I’MON Studio остаётся компоновщиком на базе единого публичного рендерера. Расширяем перенос блоков из палитры прямо в iframe, настройку композиции, CMS, GSAP и брейкпоинтов. Код Revyme не копируем.
* Если приоритет — **именно полный свободный canvas Revyme** (абсолютные координаты, timeline, компонентные variants) с закрытыми правками и без раскрытия исходного кода, предварительное условие — коммерческая лицензия и отдельный бюджет на адаптер.
* Для встраиваемых блоков/форм при дальнейшем расширении оценивать Puck MIT, но он не должен менять публичные классы/сетку и создавать отдельную неправдивую презентацию.

## Текущий измеренный разрыв (после первой CSS-проходки)

* Home desktop заголовок — 148.8px и y=60 в обеих версиях; mobile — 51.2px и y=60.
* Work mobile — 56px, исправлено с прежних 80px; первая карточка начинается вблизи исходной позиции.
* About mobile заголовок — 56px, фото ~366×201px. Русское вступление длиннее демо-текста, и высота последующих разделов отличается.
* Askona desktop крупный заголовок восстановлен в две строки; metadata и начало кейс-медиа близки к оригиналу. Mobile первое медиа начинается около y=550, как в оригинале.
* **Длины страниц пока не идентичны.** Исходная и текущая структура последующих секций требуют попарной скролл-проверки. Проход 69 HTTP+overflow проверок не является проверкой визуального соответствия.
* Внутренние имена `framer` в исследовательских файлах допустимы для разработки; на публичном сайте не должно быть отметки конструктора, чужого шаблонного агентства и неподтверждённых контактов.

## Контроль перед сливанием

1. Для каждого из 23 адресов: 1440, 810/768, 390; ссылки, файлы, брейкпоинты, типографика, композиция, формы.
2. Для каждого анимированного блока: порог появления, длительность, easing, viewport и режим reduced motion; метки из Framecoded/реального браузера являются измерением, не окончательным «оригинальным кодом».
3. Для редактора: текст -> автосохранение черновика -> просмотр -> явная публикация; блок drag/drop -> сохранение -> порядок на публичном сайте; медиа -> замена; история и права.
4. `pnpm check`, `pnpm build`, `pnpm test:studio`, Chrome workflow, чистая база после фикстур.
5. На production не включать автоматический schema push, не коммитить секреты/SQLite, не объединять экспериментальный экспорт Framecoded с сайтом без модульного и визуального аудита.

**Итог:** пока рано заявлять «1:1». Выбран путь проверяемой реконструкции, не замены одного недоделанного сайта другим.

## Практические улучшения этой ветки

- Подключены **одинаковые проверенные SVG-стрелки** вместо разнокалиберных текстовых символов в публичных блоках. Ключевая форма 24×24, stroke 1.65, единый стиль на карточках, меню и CTA.
- На холсте I’MON Studio реализован перенос **компонента из библиотеки прямо в существующую секцию через drag-and-drop**, включая выбор позиции и последующее сохранение в Payload как черновика. Тест в Chromium подтвердил появление третьего блока после перетаскивания и неизменность опубликованной версии.
- Главное видео пересжато из исходных 2880×2160 25fps 9.4 сек (24MB) в 1920×1440 около **5.8MB** и 960×720 около **1.4MB**; исходник остаётся в репозитории для дополнительной коррекции без потери качества.
- Анимации появления настроены ближе к измеренным значениям: на выгрузке Framecoded медиана in-view около **0.713 с**; большие 32px/blur3px типовые появления заменены на 12px, 0.75 c без декоративного блюра. Это измеримая коррекция, **не заявка на полное совпадение каждой GSAP-сцены**.
- Для Framecoded-выгрузки подготовлен идемпотентный типобезопасный помощник: `python3 scripts/repair-framecoded-export.py <path>`, не заменяющий ручную проверку форм/навигации и CMS.
